# Border API (M3)

`UBalloonLevelConfig`: BordersEnabled, BorderExactCount (-1 density, 0 none), BorderDensityPerKm (combined edges), BorderRadiusMinMeters/MaxMeters, BorderIntrusionFraction [0,1], BorderMinSpacingMeters, BorderAllowOverlap, BorderPolicy, BorderHeightOffsetMeters. Values are prototype tuning inputs. Border threats default disabled; do not interpret sample radii as approved enemy aggro values. Interior enemy settings belong to M4.

`BalloonBorderPlanning::Build(Config, Plan, Diagnostics)` consumes existing M2 geometry and replaces border/boundary descriptors. Counts above 10000 or more than 5,000,000 threat/cross-section diagnostic pairs fail, spacing has at most 128 attempts/item, impossible exact count fails without partial borders. Left/right offset curves use actual width evaluation and local polyline tangent. Boundary arrays align with geometry samples. Per-item Border/v1 stream is seed XOR 0x424F5231 XOR (index * 0x9E3779B9); radius drawn once, then longitudinal rejection candidates. Side alternates starting left. Changing unrelated catalogs/scenery cannot consume this stream.

`ProjectedRadius(Threat, FlightZ, HalfHeightCm)` returns -1 if sphere misses envelope, otherwise sqrt(r^2 - max(0, abs(centerZ-flightZ)-halfHeight)^2). `CrossSection` intersects the resulting disc plus horizontal balloon radius with an infinite lateral line; `UnsafeWidth` clips and unions intervals against authored corridor width. All policies except VisualOnly are unsafe for route planning. These are conservative envelope geometry queries, not engine collider sweeps or a reachability proof. Do not infer high/low bypass routes.

`ABalloonLevelGenerator::GetBorderInfluences()` copies reflected descriptors; C++ `GetPlan()` returns const plan including sampled boundaries and snapshotted envelope sizes. `DrawBorderDebug(Duration)` draws cyan boundaries, sphere volumes, flight-plane slices and labels with ID/side/radius/intrusion. Draws expire; it does not flush unrelated world debug geometry. Diagnostics include per-threat overlap counts and sampled horizontal closures. GenerateLevel remains Ready, never Complete/playable.

`ABalloonBorderThreat` is a Blueprintable stationary, non-ticking proxy. Spawn deferred, call `InitializeInfluence(Descriptor)` before finishing spawn/BeginPlay. Blocked blocks Pawn and WorldDynamic (the existing balloon uses BlockAllDynamic); Damaging/Pushback overlap these channels and dispatch `OnBalloonInfluenceEntered`; VisualOnly has NoCollision. Other channels are ignored. Blueprint effect handlers must filter OtherActor to the intended balloon; overlap events can also identify other dynamic actors. Collision geometry is the same world-space sphere. `OnInfluenceInitialized` supplies visuals. Author a Blueprint subclass for effects, damage and pushback; no BP asset is created by this milestone. Actual balloon collision object/channel compatibility requires project integration testing. Proxy initialization is rejected after BeginPlay; future runtime edits must pass the M5/M6 candidate validation transaction. Never resize collision first and validate afterward.

No automatic proxy spawning, pursuit AI, runtime radius animation, out-of-bounds consequence, or full route proof is introduced by M3.
